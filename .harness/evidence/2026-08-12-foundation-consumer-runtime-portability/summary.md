# Evidence Summary

Real Ops business smoke after consuming `pantheon-base-v0.10.18` passed CMDB (9), Deploy API (4), and Deploy UI (10), then exposed two Base-owned consumer portability gaps. The generated-module smoke asserted the producer-specific `pantheon-base/modules/...` import even though the Ops generator correctly used its own `pantheon-ops/modules/...` identity, and cleanup left the tracked feature-ledger snapshot modified after removing the temporary module.

The first patch made the shared smoke read the active repository's `go.mod`, but the `pantheon-base-v0.10.19` Ops runtime exposed one remaining layout assumption: Base keeps `go.mod` under `backend/`, while Ops keeps it at the repository root and therefore uses a `/backend` import segment. The helper now explicitly supports both layouts and resolves the backend import prefix from the module directive plus the `go.mod` location. Its Node-native `.mjs` regression entry covers both layouts in the standard smoke script suite. Cleanup restores the tracked feature-ledger snapshot from the same Git-index baseline already used for registries and i18n.

The official `pantheon-base-v0.10.20` consumer preview then exposed a release-ownership gap before apply: shared `frontend/package.json` references `scripts/go-module.test.mjs`, but that new test entry was absent from the release manifest and bundle. Ops did not apply the incomplete artifact. The release ownership contract and bundle regression now include every referenced shared script; a new immutable patch and final Ops business smoke remain required.
