# 2026-11-01-audit-p2-human-gate-preconditions — 摘要

## 一句话

三条 P2 的**动作**一个都没做（按设计归维护者），做的是让这三个动作在当天可以照着执行、
而不是现场发明：一个只读预检脚本、两份执行单、一份宣告文本。

## 为什么不是"等维护者做完"

programme 收口时这三条被登记为"归维护者"，但登记本身没让它们变得可执行：

- `AUD-013-prod` 的原话是"执行前需按 human gate 确认表内数据可丢弃并留一份导出"——
  而当时**没有任何只读手段能读出"表内有多少行"**。执行者要在"确认可丢弃"这一步做判断，
  却没有读数可看。
- `AUD-014-followup` 只有一句日期。真正要删的是 2 个路由 group、1 个中间件、2 条 CSRF 豁免、
  2 条 Casbin case、1 个测试文件 3 处、6 个文档。缺清单就得当天重新检索一遍。
- `FREEZE-DECLARATION` 只有一行"该动作归维护者"。签署人要自己从审计报告 §13、STATUS.md
  的门禁读数、11 份 manifest 的残留里拼出事实。

补前置条件不是替维护者做决定，是把"决定"和"查证"分开：查证归本包，决定归维护者。

## 三条 P2 各自缺什么 / 补了什么 / 还缺什么

### AUD-013-prod（生产库执行 000031 的 DROP）

| | 内容 |
|---|---|
| 缺 | 只读预检；执行顺序；回滚口径；放行路径 |
| 补 | `migrations/preflight/000031_preflight.sql`（6 条 SELECT）；`migrate_preflight_test.go`（逐条断言 + 验证预测成立）；`docs/runbooks/MIGRATION_000031_PRODUCTION_DROP.md` |
| 还缺 | 维护者选择放行路径 A 或 B 并签字；000031 先合入 main；实际执行 |

**本包最关键的一条发现**：DROP 与部署不可分离。`PANTHEON_AUTO_MIGRATE=false` 在生产配置里
恰恰是"走版本化迁移"的那条分支（`main.go:101 → runDatabaseMigrations → RunMigrations → m.Up()`），
而镜像只构建 `./cmd/server`。所以没有"先迁移、后切流量"的窗口——服务启动的那一刻 DROP 就发生了。
这决定了预检必须在**部署之前**做，也决定了"k8s/README 说 run migrations manually"是一个
无法执行的指示（镜像内没有那个入口）。

## 预检脚本为什么值得一个测试

它是执行者据以批准一次不可逆 DDL 的**唯一读数**。如果它低估行数，人就在错误信息上签字。
所以：

1. 脚本由测试 `//go:embed` 引入并逐条断言，而不是在 runbook 里贴副本——副本第一次有人改表结构
   就会漂移，执行者跑的就不是被断言的那份。
2. 第 3 条（将销毁多少行）与第 5 条（替换表有多少行）必须一起读：前者为 0 只说明旧表空，
   后者为 0 只说明新表空。只有「3=0」或「3>0 且 5>0 且导出已还原验证」两种组合可以继续。
3. 负向 A（第 3 条改成 `WHERE 1=0`）必须在 `rows_to_be_dropped` 上红——这是唯一能证明
   "低估会被抓住"的验证。
4. 负向 B（embed 模式放宽成 `migrations`）必须在隔离断言上红——"预检不随二进制发布"是模式
   的性质而非目录的性质，注释挡不住未来有人改模式。

## 一处自我更正

预检解析器初版按字面 `"\n;\n"` 切分语句。负向验证时用脚本改写文件，换行被写成 CRLF，
解析器把整个文件当成一条语句，报的是 `parsed 1` 而不是行数断言。

这不是负向验证失败，是**解析器对行尾敏感**——Windows 检出、或任何编辑器保存一次，都会触发。
已改为按行锚定的正则 `(?m)^;[ \t\r]*$`，并在注释里写明为什么不能按字面切分。改完后重跑负向 A，
才真正红在 `rows_to_be_dropped` 上。

顺带记一笔：如果当时把 `parsed 1` 当成"负向验证生效了"，就会留下一个在 Windows 上必然失败的
测试，并且以为它已经被验证过。
