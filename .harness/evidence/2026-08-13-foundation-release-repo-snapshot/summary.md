# Evidence Summary

The foundation release now ships a full-repository `repo.tar` snapshot, generated by `git archive --format=tar <baseCommit>`, so a consumer rebuilds deterministically from a locked release instead of a live `../pantheon-base` working tree.

`build-release-bundle.mjs` gains `createRepoSnapshot`, which writes `repo.tar` and its `repo.tar.sha256` sidecar into the dist root and packs both into the release `.tgz`; the snapshot (assetName, sha256, baseCommit, generatedFrom) is recorded in `manifest.paths.json`. `build-release-manifest.mjs` declares the `repoSnapshot` asset shape. `publish-foundation-release.mjs` verifies the `repo.tar` sha256 and uploads it (plus its sidecar) as standalone GitHub release assets.

Verification: foundation-release tests 24/24, including a new regression asserting the snapshot is byte-identical to `git archive`, its sha256 matches, it contains `config/`/`database/`/`schema/`, and it is packed into the `.tgz`. The strict encoding gate reported 0 findings. A manual `git archive` of HEAD produced a 24.8MB tar, confirming the full tracked tree is captured.
