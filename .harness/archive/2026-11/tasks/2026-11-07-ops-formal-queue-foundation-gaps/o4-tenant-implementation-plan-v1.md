## Summary and root cause

The missing capability is an opt-in business tenancy contract plus a fully scoped persistence/query path, not merely a new history table. The old route helpers omit tenant resolution (`backend/pkg/contracts/route_groups.go:13`), the scaffold rejects tenant scope (`backend/internal/scaffold/contract.go:71`), and nil tenant context removes filtering (`backend/pkg/tenant/tenant.go:278`). Observability currently uses those old groups (`../pantheon-ops/backend/modules/business/observability/observability.go:136`) and its datasource model has no tenant owner (`datasource_model.go:15`).

A private saved view could otherwise reference a global/foreign datasource; a safe route check would still leave the evaluator's bare-ID credential reads (`alert_evaluator.go:149`, `:227`). Query POST conversion also introduces audit persistence unless overrides run before denial/binding: global audit captures non-GET request/response bodies (`backend/internal/middleware/operation_log_middleware.go:223`). These are the load-bearing boundaries this implementation must close.

## Chosen minimum approach

1. Add an explicitly named Base tenant-scoped business helper. Keep `ProtectedGroup`, `ProtectedGroupWithRedis`, `DataScopedGroup` and their existing default chains unchanged. Preserve old generator output by default.
2. Reuse Base `tenant.Context`, `Scoper`, ownership helpers, membership/lifecycle checks, mode loader and Casbin/DataScope middleware. Never change nil-scoper semantics globally; reject missing context at the new opted-in boundary.
3. Implement new persistence and datasource ownership only in Ops. Reuse Arco, released Base condition/table primitives and existing cancellation/result processing. The UI AST is an intent format, not a security compiler (`frontend/src/components/operational/types.ts:46`; `conditionAst.ts:9`). No trusted backend expression compiler was identified in bounded inspection; the provider-specific compiler belongs to Ops.
4. Retain global rows as tenant0, with no inferred reassignment. Keep alert consumers legacy-only with an explicit tenant0 datasource predicate. Private-tenant alert support is a separate adoption.
5. Store server-canonical recipes using reviewed enum/catalog IDs; never store a raw expression, arbitrary label value, result, free-text name or provider error. A raw query may produce metadata-only history and cannot restore its expression.

## E. Server-owned expression restoration and audit

`query_expression.go` defines a versioned immutable **reviewed catalog**, not a sanitizer. Minimal supported recipes: Prometheus/VM approved metric IDs (e.g. availability→`up`), Loki approved label-presence/severity enums, Tempo approved service-presence filter. Store field/op/value **IDs and bounded numeric/enum parameters**, never provider-returned label values. An allowlisted field alone does not make an arbitrary value safe. Catalog values are repository-reviewed nonsecret constants; no import of provider response data into this catalog and no heuristic regex redaction.

Use typed strict JSON decoding, reject unknown fields, unsupported versions/types/operators/source-kind mismatches and excessive body/rule/depth/byte budgets. Tenant, actor, datasource URL, query string, error text, name, SQL, credentials, annotation and arbitrary literal fields are rejected, not silently dropped. Recompile against current catalog/source permissions on save/update/restore/run; stored AST is untrusted on read too. Initial safe subset need not support arbitrary OR/regex/functions: reject unsupported intent explicitly. Raw editor input stays in component/request memory, produces metadata-only history, and is never converted into a trusted recipe.

New query routes need a **route-specific audit payload guard before TokenAuth/tenant/Casbin/binding**, covering all non-GET O4 methods and aliases. Use existing `common.SetAuditParam`, `SetAuditResult`, `SetAuditErrorMsg` (`backend/pkg/common/audit.go:36`) to default to fixed safe markers; after authorization fill only tenant/actor/source/view IDs, action, safe status, counts and catalog version. Neither recipe payload nor results/provider warnings/raw errors go into audit. Parsing/validation/auth denial, upstream failure, storage error, restore failure and oversized body must keep these defaults. Global audit still records the action; do not disable it globally.

Ops `opsinit` currently applies global-header idempotency **before** observability routing (`opsinit.go:30`; `idempotency_middleware.go:45`). Its global Redis key can collide across actors/tenants and reject before the audit guard. For the exact adopted O4 route/method set, bypass this legacy middleware and let O4's bounded transactional/revision semantics own writes; alternatively route a tenant+actor key after resolution if a required idempotency contract emerges. Preserve unrelated idempotency behavior. Test equal hostile headers across users/tenants and late/revoked requests. Do not persist request/response bodies in an idempotency cache.
