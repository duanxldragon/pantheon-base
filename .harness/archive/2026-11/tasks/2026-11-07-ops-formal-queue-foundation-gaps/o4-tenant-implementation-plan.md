## Summary and root cause

The missing capability is an opt-in business tenancy contract plus a fully scoped persistence/query path, not merely a new history table. The old route helpers omit tenant resolution (`backend/pkg/contracts/route_groups.go:13`), the scaffold rejects tenant scope (`backend/internal/scaffold/contract.go:71`), and nil tenant context removes filtering (`backend/pkg/tenant/tenant.go:278`). Observability currently uses those old groups (`../pantheon-ops/backend/modules/business/observability/observability.go:136`) and its datasource model has no tenant owner (`datasource_model.go:15`).

A private saved view could otherwise reference a global/foreign datasource; a safe route check would still leave the evaluator's bare-ID credential reads (`alert_evaluator.go:149`, `:227`). Query POST conversion also introduces audit persistence unless overrides run before denial/binding: global audit captures non-GET request/response bodies (`backend/internal/middleware/operation_log_middleware.go:223`). These are the load-bearing boundaries this implementation must close.

## Chosen minimum approach

1. Add an explicitly named Base tenant-scoped business helper. Keep `ProtectedGroup`, `ProtectedGroupWithRedis`, `DataScopedGroup` and their existing default chains unchanged. Preserve old generator output by default.
2. Reuse Base `tenant.Context`, `Scoper`, ownership helpers, membership/lifecycle checks and existing IAM/session/Casbin/DataScope semantics. Add only the error-aware mode and fresh-read opt-in adapters in A; the old mode loader and old middleware cannot themselves satisfy the new contract. Never change nil-scoper semantics globally; reject missing dependencies/context at the opted-in boundary.
3. Implement new persistence and datasource ownership only in Ops. Reuse Arco, released Base condition/table primitives and existing cancellation/result processing. The UI AST is an intent format, not a security compiler (`frontend/src/components/operational/types.ts:46`; `conditionAst.ts:9`). No trusted backend expression compiler was identified in bounded inspection; the provider-specific compiler belongs to Ops.
4. Retain global rows as tenant0, with no inferred reassignment. Keep alert consumers legacy-only with an explicit tenant0 datasource predicate. Private-tenant alert support is a separate adoption.
5. Store server-canonical recipes using reviewed enum/catalog IDs; never store a raw expression, arbitrary label value, result, free-text name or provider error. A raw query may produce metadata-only history and cannot restore its expression.

### Frozen identity, provenance and two authorization stages

```go
// backend/pkg/contracts/businessauth/businessauth.go
// Every field of these ephemeral types has json:"-"; never bind them from HTTP.
type Identity struct {
    ActorID uint64
    SessionID string
    AccessToken string // request-memory only, never audit/receipt/queue/cache
    ClaimTenantID uint64
}
type RoleBinding struct { TenantID uint64; RoleKey string }
type Principal struct { Identity Identity; GlobalBindings []RoleBinding }
type Action struct { Permission, Method, Path, RouteTemplate string }
type Input struct {
    Identity Identity
    Resolution tenant.Context // frozen Mode, TenantID and ResolvedBy
    ResourceTenantID uint64
    Action Action
    DataScope bool
}
type Authorization struct { DataScope *common.DataScopeReq; Bindings []RoleBinding }
type Reader interface {
    RefreshPrincipal(context.Context, Identity) (Principal, error)
    Authorize(context.Context, Input) (Authorization, error)
}
```

Identity is constructed by Base immediately after the new opt-in BusinessTokenAuthMiddleware from a freshly authenticated opaque session plus its request-memory token; the legacy TokenAuthMiddleware is not in this opted-in chain. Revalidate Redis token→actor/session/claim equality, positive TTL, user and session blacklist independently (only redis.Nil means absent), active `system_user_session` ownership/revoked/expiry/idle state and current enabled/not-deleted user. Reuse `authtoken.ValidateSession` (`token.go:138`), existing blacklist key helpers (`token_middleware.go:159`) and `authsession.ApplyActiveScope` (`session_scope.go:22`); ValidateSession alone does not check revocation. No stale in-memory session or user-dept cache authorizes a checkpoint. This new fresh behavior is opt-in; do not weaken or globally rewrite old TokenAuth.

**Mandatory opted-in order:** BusinessTokenAuthMiddleware (fresh read; no activity writes) → RefreshPrincipal (fresh actor/user/session/blacklists and **actual tenant0 role bindings**) → strict mode read → tenant resolution with that principal's global capability → Authorize (fresh resolved binding/action/DataScope) → handler binding. The latter stage owns the new route's Casbin/DataScope enforcement using existing algorithms; do not insert old Casbin/DataScope before it or feed mixed bare role keys into them. That would reintroduce stale denial/grants and namespace promotion (`casbin_middleware.go:22`, `data_scope_middleware.go:102`, `tenant/authz.go:449`). PlatformScope=false uses strict Resolve semantics; true permits only the established platform fallback. Ops datasource/history/view declare true to retain tenant0 population access; tenant0 always selects tenant0 rows.

Freeze provenance from `tenant.Resolve` itself, not an untrusted body flag. For valid compat use global0 bindings/policy and no membership check. In multi, claim/member resolution requires active membership/lifecycle of the claim/resource tenant and reads **that tenant's** current user-role/role join plus separately verified actual global0 bindings. Evaluate genuine global grants first, then that member namespace, preserving existing order without promoting bare tenant keys; a global grant does not waive the claim's membership/lifecycle check. Platform header override requires current real global bindings and platform grant for the action, validates target lifecycle (unless0), and retains global binding tenant0 while resource tenant may be positive; it does not require target membership or acquire target roles merely by specifying a header. Claim-less platform fallback additionally requires no active memberships and current global capability. Tenant-local roles with a key such as admin/platform_ops never become global bindings. A session with a positive claim must itself still be valid for that claim; header override cannot resurrect a revoked originating session/membership. On every recheck, verify the frozen provenance remains authorized; do not resolve to a new tenant halfway through the request.

**Opt-in authentication prerequisite (revision3 CODE HIGH1):** Add `BusinessTokenAuthMiddleware(rdb *redis.Client) gin.HandlerFunc` in Base `backend/internal/middleware/business_token_middleware.go`, with dedicated tests. It reuses `extractToken`, `authtoken.ValidateSession`, blacklist key helpers and `applyTokenContext`, but never uses the legacy in-memory token cache, `refreshTokenActivity` or `RefreshSessionActivity`. Every request checks live token existence and positive PTTL plus blacklists; missing/nil/cancel/error denies before constructing Identity. Read identity equality again in RefreshPrincipal. No Redis activity SET/TTL issuance, SQL session activity write or stale-cache grant occurs in this new middleware. The first implementation deliberately does not refresh activity from O4 queries: established auth/session refresh endpoints retain their existing lifecycle and the current idle/hard-expiry rules remain enforced by the fresh reader. This explicit read-only choice avoids a new refresh protocol; a future opt-in activity writer requires atomic existing-value/positive-TTL conditional update and separately reviewed no-resurrection tests. Legacy exported middleware/defaults retain their signatures and route/cache defaults. A narrow shared safety prerequisite changes authtoken.RefreshSessionActivity: atomically require the existing Redis session key with positive PTTL, update its payload preserving the remaining expiration, and return an explicit error for a missing/expired/persistent key or store failure. Never use fallback AccessTokenTTL or recreate a key. Use Redis Lua (existing client) for the indivisible existence/PTTL/write; preserve millisecond precision, and compare the current payload identity or opaque original bytes before replacing it so a concurrent different session cannot be overwritten. Existing old TokenAuth activity calls share this writer, so merely avoiding writes in the new chain cannot close the cross-route expiry/deletion race. The prerequisite closes revision3 CODE HIGH: an old login-tenants request that loaded a token before deletion/expiry must not resurrect it before the new entry or provider release check. No signature, cache/default route or session issuance change; StoreSession remains the separate issuance path. Tests cover expiration/deletion after old route read, no-TTL keys, unrelated replacement payload, Redis/cancellation failure, live-key update without TTL extension, and old activity/new fresh entry/release-check interleavings with zero provider call. Base auth Generator owns token.go/token_test.go and necessary middleware regression fixtures. Do not change legacy middleware authorization semantics beyond refusing unsafe activity writes; new business fresh checks independently deny invalid sessions. Test deletion/expiry between first token read and principal validation, TTL/store errors and cached legacy payload: no token resurrection, no provider/history/route handler call. Also preserve legacy middleware regressions. This new middleware belongs to Base auth Generator and the sealed candidate inventory, not an Ops override.

Base owns the adapter `backend/modules/auth/login/business_authorization.go` on the existing Runtime, reusing `GetUserRolesForTenant(userID,tenantID)` (`login_runtime.go:328`) and its joined tenant constraints; annotate the namespace actually queried, do not use owning-tenant-only `UserService.GetUserRoles` for a multi-membership action. ## Material tradeoffs for critic

| Decision                                                 | Benefit                                                                                 | Cost / limit                                                                                                                 |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| New opt-in helper, legacy defaults retained              | Small blast radius and explicit resource adoption                                       | Two route families to document; alias/startup wiring must be tested                                                          |
| Legacy0 alerts, private datasource support only in O4    | Avoids widening to alert/channel tenancy; retains existing global rules                 | Private tenants cannot create alerts on private sources yet; deliberate rejection must be visible                            |
| Server enum/catalog recipes, raw histories metadata-only | Strong nonsecret persistence with reproducible restoration                              | Arbitrary raw expressions and custom names cannot be restored; smaller supported expression language                         |
| Guard row + transactional budgets                        | Enforces count/bytes under concurrent cross-source writes                               | Additional tiny table/lock ordering; quotas serialize one owner's writes                                                     |
| Error-aware/fresh Base read adapters                     | Denies mode, binding and session failures at entry and release using existing authority | More DB/Redis reads; initial current-policy snapshot avoids a second cache/framework                                         |
| Dedicated candidate artifact + exported assembly seam    | Allows paired integration before release with honest source identity                    | New producer/resolver review and sealing work; formal release/consumption remains open                                       |
| Versioned schema + retained-down + supported wrapper     | Preserves data while refusing incompatible artifacts on supported startup               | No retroactive protection for directly launched old binaries; exclusive dirty recovery and stopped-old-process gate required |
| POST query and strict URL boundary                       | Avoids product URL literal persistence and enables safe audit controls                  | Legacy GET deprecation and Tempo provider transport need explicit compatibility evidence                                     |

- **Antithesis (steelman):** existing helpers, IAM, loader, generator and assembler already carry most capabilities; adding public ports, registries, candidate protocol and a startup command risks turning O4 into a second platform framework. Preserve their semantics and use smaller adapters wherever they actually meet the new contract. Actor-only delivery would lower effort but does not meet the authorized O4 decision/packet (`:37`).
- **Tradeoff tension:** legacy reuse reduces blast radius but preserves real failure-to-compat, stale-session roles, audit-after-capture and stable-release-only resolution. Strong fresh authorization costs reads; retained schema needs an external supported startup gate that old binaries cannot supply themselves. These costs cannot be removed by promising isolation in middleware alone.
- **Synthesis:** additive business opt-in over existing IAM/session/Casbin/DataScope, a leaf error-aware mode reader, metadata-only audit strategy and candidate adapter around exported seams. Limit adoption to datasource/history/views, retain empty guard rows, forbid unsupported relations/private alerts/arbitrary recipes, preserve old exports/defaults and keep all four contract prerequisites plus honest runtime/official-consumption limits.
