## 任务背景

阶段一已完成文本色层次和字号体系的对齐，将总体对齐度从 70% 提升到 85%。

阶段二聚焦于**容器语义**、**响应式断点**和**密度策略**三个维度，目标是将对齐度提升到 **95%**，建立与蓝鲸设计规范同级的工程化设计系统。

## 三大任务

### Task 5: 重构容器 Token ⏳

**问题**: 当前 `--panel-*` token 混用于交互和展示场景  
**目标**: 区分交互容器（input/button）和展示容器（panel/card）  
**预计**: 2h  
**产出**: 
- 8 个新 token（interactive 4 个 + display 4 个）
- 至少 5 个组件迁移
- 交互态更明显，展示态更弱

### Task 6: 补充 1024px 平板断点 ⏳

**问题**: 只有 768px/1280px 两档，iPad 横屏（1024×768）布局跳变  
**目标**: 补充 1024px 断点，形成 768/1024/1280 三档体系  
**预计**: 1.5h  
**产出**:
- 新增 `--breakpoint-tablet-lg: 1024px`
- 侧边栏/SearchToolbar/表格适配平板横屏
- iPad 体验优化

### Task 7: 完善全局密度策略 ⏳

**问题**: 只有单一密度，数据密集页面不够紧凑  
**目标**: 建立 compact/default/comfortable 三档密度  
**预计**: 1h  
**产出**:
- 三档密度 token
- 表格/表单/卡片适配密度变量
- `useDensity` hook 支持切换

## 执行策略

### 顺序执行（推荐）

```
Task 5 (容器 token) → Task 6 (断点) → Task 7 (密度)
     ↓                      ↓              ↓
  基础 token         响应式布局       交互体验
```

**理由**：
- Task 5 定义的容器 token 会被 Task 6 的布局规则引用
- Task 6 的断点会影响 Task 7 在不同屏幕下的密度表现

### 并行执行（高级）

如果你有多个开发者：
- 开发者 A: Task 5 + Task 7（都是 token 定义，冲突少）
- 开发者 B: Task 6（布局调整，独立性强）

最后合并时优先 Task 5，再 Task 6/7。

## 风险管理

### 已识别风险

1. **容器 token 迁移可能影响现有样式** (中等风险)
   - 缓解: 保留旧 token，渐进迁移
   - 验证: 每迁移一个组件验证一次

2. **1024px 断点可能与现有断点冲突** (中等风险)
   - 缓解: 只新增中间档，不改变现有 768px/1280px
   - 验证: 测试三个临界值 767px/1023px/1279px

3. **密度切换可能导致布局错乱** (低风险)
   - 缓解: 只影响间距和行高，不改变结构
   - 验证: 三档密度都测试关键页面
