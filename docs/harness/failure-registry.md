## Review Notes

- Repeated failures: CI signal noise (including advisory jobs that fail silently — FR-010, and the long-standing red advisory `Core Smoke` — FR-011, root-caused on 2026-09-20 by `.harness/evidence/2026-09-20-smoke-core-tenant-ci-gap/`), historical static-analysis maintainability debt, security boundary drift, smoke scope drift, unrecorded ratchet events, cache hygiene, and sibling-path method wrappers are now tracked.
- FR-011 is `implemented`: the suite-membership and environment split is now explicit in `frontend/package.json`, `.github/workflows/smoke-core.yml`, and `frontend/tests/smoke-core/README.md`; the tenant matrix job owns its multi-mode prerequisites and `tenantmatrixdb` rejects unknown mode values. Hosted CI remains the required runtime evidence for the new tenant job.
- FR-012 and FR-013 are `implemented` as sensors rather than gate changes: process-local caches keyed by a recycled object address now carry a deterministic invariant test plus a foreign-verdict scenario test, and browser layout measurements go through a shared `settleElementLayout` that waits for the box signature to stabilise and for `getAnimations()` to finish. Both fixes remove the race instead of relaxing an assertion, so the pre-existing bounds stay in force.
- FR-014 is `implemented` as a gate rather than a sensor, because the failure was not a wrong reading but an absent one: nothing anywhere observed a published release, so three consecutive releases shipped unconsumable. `check-release-assets.mjs` verifies the four-asset set and its checksums by reusing the publish path's own `validateReleaseAssetChecksum`, and `foundation-release-verify.yml` runs it on `release: published` so the state is caught at the moment it is created rather than by the next consumer. Repairing `v0.14.0`, `v0.15.0` and `v0.16.0` is deliberately left to a separate, manually dispatched `foundation-release-backfill.yml` run (dry-run by default), and promoting the new check to a required check is left to a maintainer.
- FR-015 is `implemented` as a widened gate plus regression tests: the release preflight now scans both published shapes (`bundle/` and `repo.tar`), fails closed when the snapshot is missing, and pins the exact v0.17.0 residue path under `.harness/archive` in `repo.tar`. The post-publication scan of the real v0.17.2 assets found them clean, so the gap was in the gate's coverage, not in the shipped release.
- FR-016 is `open`, deliberately not `implemented`: the 31 red lines were closed by backfilling structure only — no historical `commands[].status`, verdict or gap judgement was rewritten, and each added string restates text already present in that round's own `review.md` / `summary.md` / `commands.json`. The failure itself was the absence of an observer: `check-evidence.mjs --strict` and `check-review.mjs --strict` validate the evidence contract but are not referenced by any workflow, so a schema requirement added after a round silently rotted that round's artifacts. Wiring the two into `.github/workflows/quality.yml` is a gate-policy change and is left to the maintainer; until then the registry records the recommendation and the chain is only green because it was run by hand.
- FR-017 is `open` with a `guide-updated` promotion only: all three red readings were closed as facts on 2026-10-26 — 11 `runtimeGap` strings appended to the historical `commands.json` files (1 insertion / 0 deletions each, no `commands[].status` line touched), the `MenuNode` boundary ratchet executed so `config/boundary-baseline.json` is now empty, and the 8 inheritance findings closed by adding the marker sentences the checker requires plus a pinned `Base version` for `pantheon-ops`. What is still missing is the observer: `check-runtime-evidence` and `check-inheritance-contract` remain in no workflow and no npm script, and `check-boundaries` runs only with a baseline, so a fresh violation of either class is still invisible until someone runs the chain by hand. The guide change records the invocation forms that were being misread (`--root ..` for the workspace-scoped checker, bare `--strict` versus the CI `--baseline` form) in `scripts/harness/README.md` and `scripts/harness/README.zh.md`; promoting any of the three to a blocking CI step is a gate-policy decision left to the maintainer, as with FR-016.
- FR-018 is `implemented` with a `guide-updated` promotion: `docs/harness/AI_QUALITY_GOVERNANCE.md` §5.2 now requires static-analysis fixes (e.g. Sonar `S3776`) to be re-measured with the same rule before commit, with the before/after readings recorded. The trigger was concrete — `.harness/evidence/2026-10-28-release-gate-green` claimed TenantList.tsx's `typescript:S3776` was cleared by a `can(perm)` helper, PR #463 merged on that claim, and `main` `1ae6481c` still reported the finding at 16. Local re-measurement reproduced 16 before and after the helper, and the four-state branch extraction into `renderBody()` measured 16 → 10. The sensor stays advisory-by-hand (the plugin is not a repository dependency) because `sonarcloud-gate` already owns the authoritative reading; the gap the guide closes is the missing pre-commit measurement, not a missing gate.
- FR-019 is `implemented` as a sensor: `resolveArchiveAwarePath` resolves the canonical `.harness/tasks/...` and `.harness/evidence/...` references against both the live tree and the monthly archive, so a task packet, a review document or the archive index can keep naming the task id after the files move.
