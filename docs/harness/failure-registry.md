## Review Notes

- Repeated failures: CI signal noise (including advisory jobs that fail silently — FR-010, and the long-standing red advisory `Core Smoke` — FR-011, root-caused on 2026-09-20 by `.harness/evidence/2026-09-20-smoke-core-tenant-ci-gap/`), historical static-analysis maintainability debt, security boundary drift, smoke scope drift, unrecorded ratchet events, cache hygiene, and sibling-path method wrappers are now tracked.
- FR-011 is `implemented`: the suite-membership and environment split is now explicit in `frontend/package.json`, `.github/workflows/smoke-core.yml`, and `frontend/tests/smoke-core/README.md`; the tenant matrix job owns its multi-mode prerequisites and `tenantmatrixdb` rejects unknown mode values. Hosted CI remains the required runtime evidence for the new tenant job.
- FR-012 and FR-013 are `implemented` as sensors rather than gate changes: process-local caches keyed by a recycled object address now carry a deterministic invariant test plus a foreign-verdict scenario test, and browser layout measurements go through a shared `settleElementLayout` that waits for the box signature to stabilise and for `getAnimations()` to finish. Both fixes remove the race instead of relaxing an assertion, so the pre-existing bounds stay in force.
- Sensors with false positives: broad smoke can over-block unrelated PRs when used as a main quality gate.
- Sensors with known false negatives: local checks still depend on agents recording task packet, evidence, and review artifacts for non-trivial work.
- Rules to remove or downgrade: Codacy remains informational only; `Full Smoke Suite` stays scheduled, manual, or release-precheck.
- Next harness changes: measure whether new-code duplication and security-boundary regressions recur after the task template and failure registry schema upgrade.
